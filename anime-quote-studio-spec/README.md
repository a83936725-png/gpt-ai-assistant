# Anime Quote Studio 開發包｜使用說明（給你自己看的）

## 這包裡有什麼

| 檔案 | 給誰看 | 放到新專案的位置 |
|---|---|---|
| `README.md` | 你 | 不用放 |
| `SPEC.md` | AI | `docs/SPEC.md` |
| `AI_RULES.md` | AI | Claude Code → `CLAUDE.md`；Cursor → `AGENTS.md` |
| `TEST_CASE_YOUTUBE.md` | AI | `docs/TEST_CASE_YOUTUBE.md` |
| `PHASE_PROMPTS.md` | 你（複製裡面的 Prompt 貼給 AI） | 不用放 |

## 交給 AI 的步驟

1. 建一個空資料夾，例如 `anime-quote-studio`，執行 `git init`。
2. 依上表把檔案放進去。
3. 用 AI 工具打開這個資料夾，貼 `PHASE_PROMPTS.md` 的 **Prompt 0**。它只會給計畫，不寫程式。
4. 看完計畫，特別注意第 6、7 點（它做不到什麼、規格哪裡有問題）。確認後再依序貼 1A → 1B → 1C → 2 → G1 → G2 → 3A → 3B → 4 → 5。圖文（G）和影片剪輯（3）互不相依，想先要哪個就先做哪個。
5. 每一步都要**自己實際點一遍**，不要只看 AI 的報告。

## 你指定的 YouTube 影片

`https://www.youtube.com/watch?v=Ac3LTZ4GgG0&list=...&index=19` 已寫進 `TEST_CASE_YOUTUBE.md`，作為：
- 網址解析測試（這個網址帶有播放清單參數，剛好可以測「只分析這一部、不展開整個清單」）
- Phase 4 YouTube 模式驗收
- 全部測試完成後，用它跑一遍完整操作並製作有真實截圖的操作說明（`docs/USER_GUIDE.md` 與站內 `/help` 頁）

**關鍵問題：這部影片是不是你自己頻道上傳的？**
- **是**：你可以從 YouTube Studio 官方下載 MP4，再上傳到系統，跑完整的剪輯與輸出流程。
- **不是**：系統只能做「純文字模式」（看資訊、嵌入播放、用你有權使用的字幕檔做翻譯與金句分析、點金句跳轉）。剪輯與 MP4 輸出會被系統擋下，而且擋下本身就是要測的項目。完整剪輯流程請用另一部你有權使用的影片測試。

AI 實測時會先問你這個問題。

## 角色圖文（你新加的功能）

流程固定為：**選角色 → 選他說過的台詞 → 上網搜集背景 → 你確認資料 → 產生圖文 → 匯出**。
預設產出 5 張 IG 直式（1080×1350）卡片：封面金句 → 角色介紹 → 台詞劇情背景 → 台詞解讀 → 出處，另附貼文文案與 hashtag。

| 我加的設計 | 為什麼 |
|---|---|
| 每條背景資料都要附來源網址＋原文摘錄，系統自動比對摘錄真的在那個網頁上 | AI 很會編角色設定，這樣才擋得住 |
| 劇透等級：無劇透／只到這一集／不限制 | 角色背景很容易爆雷 |
| 只有你確認過的資料才會放進圖文 | 網路資料常互相矛盾，最後由你決定 |
| 不自動抓網路上的角色圖 | 官方立繪、截圖都有版權；背景改用你有權利的影片畫面、你上傳的圖或模板 |
| 「台詞解讀」卡會標示是解讀 | 觀點和事實要分開 |
| 文字太長會警告，不會被默默切掉 | 中日文排版最常出這個問題 |
| 冷門角色找不到資料就說找不到 | 改用影片內容＋你手動輸入，不讓 AI 亂編 |

## 我修正了原需求中會讓 AI 出錯的地方

| 原需求 | 問題 | 修正 |
|---|---|---|
| BullMQ 或 Celery 擇一 | BullMQ 是 Node.js 用的，後端是 Python | 鎖定 Celery |
| PostgreSQL＋Supabase | 兩個並列，AI 會搖擺 | 先用本機 PostgreSQL，Phase 4 再評估 |
| 「取得 YouTube 字幕」 | YouTube 官方 API 只能下載**你自己影片**的字幕 | 別人的影片改成上傳有權使用的字幕檔，走純文字模式 |
| AI 不可編造台詞 | 只靠 Prompt 叮嚀擋不住 | LLM 只回傳段落 ID，台詞由系統從資料庫組回，結構上無法造假 |
| 用秒數記時間 | 浮點誤差會讓字幕越來越偏 | 全部用整數毫秒 |
| 直接播放上傳的影片 | 瀏覽器播不了 MKV 和部分 MOV | 上傳後自動產生預覽用 MP4 |
| 直式裁切 | 容易切掉人物 | 預設「模糊背景」模式，裁切改成選項 |
| 剪輯合併 | 不同解析度／幀率的片段直接合併會失敗，用 `-c copy` 切片會黑畫面 | 每段先重新編碼成相同規格再合併 |
| 字幕同步 | 剪輯後的字幕時間要重新計算，最容易出錯 | 獨立模組＋必須有單元測試，燒錄字幕與 SRT 共用同一份計算結果 |
| 中日文字幕 | Docker 裡沒有中日文字型，字幕會變方框 | 映像檔內安裝 Noto Sans CJK TC/JP |
| Whisper 辨識 | 遇到純音樂會生出「ご視聴ありがとうございました」這類幻覺字句 | 加入過濾與低信心標記 |
| 畫面張力評分 | 第一版只有文字，AI 看不到畫面 | 標示「依文字推估」，Phase 5 有影格分析後再改 |

## 每個階段要特別盯的事

- **AI 說「完成」不代表能用。** 請它附上實際執行的指令與輸出；沒附的就當作沒測。
- **抓假實作：** 每個 Phase 結束時貼「抓假實作」Prompt（在 `PHASE_PROMPTS.md` 最下面）。
- **它想改測試讓測試通過時要擋下。** 除非它能解釋測試本身哪裡錯。
- **對話太長時開新對話**，貼「接續進度」Prompt，它會從 `PROGRESS.md` 和 git 紀錄接上。
- **每個 Phase 結束都要 git commit**，改壞了才能退回。
- **雲端 AI 開發環境可能連不到 YouTube**（我產生這份文件的環境就連不到）。Phase 4 和實測最好在你自己的電腦上跑。
