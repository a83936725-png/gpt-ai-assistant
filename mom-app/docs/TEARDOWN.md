4. 最後有轉換按鈕（預約）→ 對品牌來說就是「導購／加 LINE」。

## 三、產品定位（給易家滴雞精）

- **品牌任務**：滴雞精的主要使用時機（備孕、孕期、坐月子、哺乳）剛好就是這個 App 的使用旅程。App 是每天會打開的「工具」，品牌出現在對的時刻，而不是廣告。
- **每日接觸點**：「今天的滴雞精時光」打卡卡片（首頁）＋可設定的每日提醒 → 養成習慣、提高回購。
- **導流**：品牌頁與島上小舖的「官網選購」「加入 LINE 好友」按鈕（`config.js` 設定）。
- **可延伸的會員機制（第二階段）**：連續打卡集點 → 兌換優惠券；LINE 官方帳號推播。

### ⚠️ 法規與信任（很重要）

1. **食品不能宣稱療效**（食品安全衛生管理法第 28 條）：App 內所有滴雞精相關文字都只談「習慣、休息、心情、保存加熱方式」，沒有「促進傷口癒合、補氣、退奶」這類說法。之後新增文案也請維持。
2. **健康資料屬於敏感個資**（個人資料保護法第 6 條：醫療、健康檢查等）：MVP 版本資料只存在使用者自己的手機，不上傳。第二階段要做雲端同步時，需要明確的告知同意、加密與存取控管。
3. **醫療資訊**：所有衛教內容標示「一般衛教資訊，不能取代專業醫療建議」，疫苗／產檢時程都註明「以疾管署／國健署公告及醫師安排為準」。上線前建議請合作的醫師或營養師審閱內容。

## 四、技術架構

- **純前端 PWA**：HTML + CSS + 原生 JavaScript，不需要編譯、不需要伺服器、不需要資料庫。可以「加入主畫面」當 App 用，也能離線使用。
- **資料**：存在瀏覽器 localStorage（`yijia-mom-app-v1`），結構見 `js/store.js`。
- **模組化**：每個功能是一個檔案，透過 `App.screen()`／`App.homeCard()`／`App.tool()` 註冊。

```
mom-app/
├── index.html            入口
├── config.js             ★ 品牌設定（名稱、LOGO、官網、LINE 連結）
├── manifest.webmanifest  PWA 設定
├── sw.js                 離線快取＋通知點擊
├── assets/               LOGO、App 圖示
├── css/                  base（設計系統）＋各模組樣式
├── js/
│   ├── core.js           日期、孕週、排卵、預測、母乳保存、WHO 百分位（有單元測試）
│   ├── store.js          資料儲存
│   ├── ui.js             UI 元件（底部抽屜、提示、表單）＋模組註冊
│   ├── app.js            路由、分頁列、即時計時器
│   ├── data/             紀錄類型、好孕島內容、疫苗/里程碑/WHO 表、孕週資料
│   └── modules/          home 首頁｜babylog 紀錄｜milk 母乳庫存｜island 好孕島｜
│                         health 成長健康｜pregnancy 備孕懷孕｜brand 品牌｜me 我的
├── tests/                core.test.js 單元測試｜e2e／extended／journey.playwright.cjs 瀏覽器測試
└── docs/TEARDOWN.md      本文件
```

### 換成正式 LOGO

目前的 LOGO 是依你提供的圖重新描繪的向量檔（`assets/logo.svg`、`assets/logo-full.svg`）。若要用原始檔：
1. 把原圖放到 `mom-app/assets/logo.png`（建議透明背景、正方形）
2. 打開 `config.js`，把 `logo: 'assets/logo.svg'` 改成 `logo: 'assets/logo.png'`

### 部署（任選一種，免費）

- **Vercel**：新增一個專案 → 選這個 GitHub repo → Root Directory 設為 `mom-app` → Framework 選 Other → Deploy。
- **GitHub Pages / Netlify**：把 `mom-app` 資料夾當成靜態網站發佈即可。
- 本機預覽：`cd mom-app && python3 -m http.server 8080`，打開 http://localhost:8080

> 注意：iPhone 要收到通知，需先用 Safari「加入主畫面」，再從主畫面打開 App 開啟通知（iOS 16.4 以上）。

## 五、第二階段路線圖

| 優先 | 項目 | 做法 |
|---|---|---|
| 1 | **LINE 登入＋雲端同步＋家庭群組** | LINE Login／LIFF 取得使用者；後端（例如 Vercel Functions + Postgres，或 Firebase／Supabase）存資料；家庭邀請連結讓多人即時共用同一個寶寶的紀錄 |
| 2 | **關閉 App 也能收到推播** | Web Push（VAPID）＋排程；或改用 LINE 官方帳號推播（品牌也能一起經營） |
| 3 | **串接這個 repo 的 LINE 機器人** | 在 LINE 對話裡打「瓶餵 120」就寫入紀錄；也可以接上原本的 AI 助理做育兒問答（需加醫療安全護欄） |
| 4 | **寶寶攝影機** | WebRTC 點對點視訊＋信令伺服器（必要時 TURN），舊手機／平板當攝影機 |
| 5 | **會員點數** | 滴雞精打卡集點 → 優惠券／官網折扣碼 |
| 6 | **上架 App Store／Google Play** | 用 Capacitor 包裝，或 Android 用 TWA |
| 7 | **好孕島升級** | three.js 3D 版、角色選擇、更多隱藏彩蛋、醫師／營養師專欄 |

### 資料安全（0.6.6）

紀錄只存在手機的瀏覽器裡，而瀏覽器給每個網站大約 5 MB。實際量過：一個寶寶每天約 23 筆紀錄，1 年用掉 37%、2 年 73%；雙胞胎 2 年就超過上限。舊版在存不下時**不會有任何提示**——新紀錄看得到，但關掉 App 再打開就不見了（用 0.6.5 實測：雙胞胎 2½ 年 43,201 筆，重開後剩 0 筆）。

現在：

| 情況 | 怎麼處理 |
|---|---|
| 一般使用 | 紀錄存得更精簡（空白欄位不存、時間存成數字，讀回來完全一樣），同樣空間大約可多存一半 |
| 存了幾年、空間不夠 | 自動改存到手機的資料庫（IndexedDB，空間大很多），不會少任何一筆；並請瀏覽器不要因空間不足而清掉 |
| 剛按完就關掉 App | 每次存檔都會另外立刻留一份「最近 7 天＋所有設定」；就算資料庫還沒寫完就關掉，下次打開也會補回最新的紀錄、修改和刪除 |
| 資料很多時的速度 | 先更新畫面、隨後再存檔（連續按會合併成一次）；切到別的 App 或關掉時會立刻存。2½ 年雙胞胎的資料，在比電腦慢 4 倍的手機上，一鍵記錄從 0.93 秒變成 0.24 秒 |
| 真的存不了（手機完全沒空間） | 立刻跳出提醒，首頁和「我的」顯示紅色卡片和「立刻匯出備份」按鈕，直到存成功才消失 |
| 「我的」 | 顯示紀錄筆數、用了多少空間（或已改存資料庫）、上次匯出備份是幾天前 |

另外修好家人合併漏資料：「匯入／合併家人的備份」原本只合併寶寶紀錄、成長、疫苗、產檢日期等，**身體狀況日記、產檢筆記（體重、血壓、醫師交代）、產後恢復紀錄、生產日、孕產路線圖勾選、葉酸與每日小任務都不會合併**；在新手機（例如爸爸第一次匯入媽媽的備份）也不會帶入預產期和階段。現在全部會合併；新手機直接沿用對方的設定，已經在用的手機只補空白、不改自己的設定。

時間軸掃描另外抓到：照護報告的疫苗表在小手機上會超出畫面 5–7px（某些月齡、狀態欄出現「自費・可補打」時）。改成三欄（疫苗・劑次／狀態／日期），劑次與「12 天後到期」不會被拆成兩行，表格下方註明「日期：已完成者為接種日，其他為建議接種日」。

測試：新增 `tests/data-safety.playwright.cjs`（22 項）：壓縮後關掉重開逐欄位一模一樣、舊版資料照常開、雙胞胎 2½ 年 42,000 筆自動改存資料庫且重開全部都在、資料庫還沒寫完就關掉也能補回（含修改與刪除）、空間滿會提醒且紀錄不丟、匯出→新手機取代完全一致、家人合併三種情境、壞檔案不影響現有資料。

### 雙胞胎、資料保護提醒、會員 API 安全（0.6.7）

**雙胞胎計時錯寶寶（已修好）**：親餵、睡眠、擠奶的計時原本整個 App 只有一個。大寶開始睡覺後切換到小寶，按「醒來了」，這段睡眠會記在**小寶**身上；小寶也睡著時再按一次，會**蓋掉大寶正在計時的睡眠**。現在每個計時都記得是哪個寶寶的：

- 兩個寶寶可以同時睡、同時親餵，各自計時、各自換邊
- 計時列會寫上寶寶的名字（「大寶・睡覺中」），按下去就是那個寶寶的
- 刪除寶寶時，那個寶寶正在跑的計時也一起移除
- 只有一個寶寶的家庭資料格式完全不變；舊版留下的計時算在當時選的寶寶身上
- 擠奶是媽媽自己的，維持一個計時

**防止資料被清掉的提醒**：iPhone 的 Safari 如果 7 天沒開這個網站，會清掉存在手機裡的資料，除非把 App 加到主畫面。首頁現在會（有 20 筆以上紀錄時、一次只出現一張）：

- 在 iPhone／iPad 的 Safari、還沒加到主畫面時，教三步驟「加入主畫面」（按「知道了」就不再出現）
- 30 天沒匯出備份時，提醒匯出一份（第一週不打擾，「下週再說」延後 7 天）

**會員 API 安全強化**：另外請一個獨立的審查對會員 API 做了攻擊測試，沒有發現能讀取或修改別人資料、植入程式碼的漏洞；找到並修好：

| 問題 | 修好後 |
|---|---|
| 用 Redis（Vercel KV）時，「登出所有裝置」可能被同時進行的資料更新蓋回去，被偷的登入憑證仍可用 | 憑證版本另外存、只會往上加 |
| 任何人輸錯 11 次密碼就能鎖住任何會員（本人輸對也進不去） | 改成「同帳號＋同網路」10 次；同帳號不分網路 50 次，但本人登入過的網路不受影響 |
| 伺服器在代理後面時，所有人共用一份次數限制（11 次垃圾註冊就讓全站無法註冊）；IPv6 每個位址各算一份 | 新增 `MOM_TRUST_PROXY` 設定；IPv6 以 /64 計算；輸入錯誤不算進註冊次數 |
| 一個網路可灌 40 個假的在線人數 | 每個網路 10 分鐘最多 6 個新連線 |
| 正式環境以外，很短的 `MOM_AUTH_SECRET` 也能用（拿到一個憑證就能猜出密鑰） | 少於 32 字一律不用 |

| 密碼雜湊強度低於 OWASP 建議；常見密碼可註冊 | 強度提高 5 倍（記憶體用量不變），舊密碼下次登入自動升級；常見密碼擋下 |
| Redis 的次數計數若設定到期失敗會變成永久鎖住 | 遞增與到期改成單一指令 |
| LINE 登入的 state 可重複使用，讓伺服器一直用我們的密鑰呼叫 LINE | state 只能用一次，回呼也限次數 |
| 測試檔、內部文件可以從網站直接下載 | 不再公開（伺服器擋下，`.vercelignore` 不部署） |
| 同一個網路可以灌邀請人數 | 每個網路每個邀請碼每天最多算 3 位 |

**還需要決定的**：Email／簡訊驗證與忘記密碼（需要串接寄信或簡訊服務）。在那之前，任何人都能用別人的 Email／手機註冊，註冊時也會透露號碼是否已經在用；邀請人數換網路仍可灌。詳見 GROWTH.md「安全設計」。

### 個資檢查與勾選同意（0.7.4）

依《個人資料保護法》檢查會員登入與社群功能（條文：[全國法規資料庫](https://law.moj.gov.tw/LawClass/LawAll.aspx?PCode=I0050021)）。

**檢查結果與處理**

| 問題（依風險排序） | 依據 | 處理 |
|---|---|---|
| 註冊蒐集 Email／手機，卻**沒有個資告知、沒有同意**，也無法證明對方同意過 | 第 8 條（告知事項）、第 7 條（同意的舉證責任在蒐集者） | 新增「隱私權政策與使用條款」頁；註冊時必須勾選「我已閱讀並同意」（預設不勾），伺服器拒絕沒有同意的註冊，並把**同意的版本與時間**存在帳號裡 |
| 沒辦法在 App 裡下載自己的資料或刪除帳號 | 第 3 條（查詢、複製本、更正、停止、刪除） | 我的 → 帳號：修改暱稱、下載我的會員資料（JSON，不含密碼）、刪除帳號（密碼帳號要再輸入一次密碼；嘗試次數有限制） |
| 行銷沒有獨立同意，也沒有關閉方式 | 第 20 條 | 另一個**選填、預設不勾**的「願意收到優惠與活動訊息」；帳號卡有開關，可隨時免費關閉 |
| 用來擋猜密碼的網路位址雜湊沒有金鑰，IPv4 可以被反推 | 資料保護 | 改用伺服器密鑰的 HMAC，存的值無法還原 |
| 社群功能、祝福牆（含親友的名字與祝福）沒有勾選同意 | 第 8 條、第 6 條 | 島上的媽媽、同週好孕圈、開祝福牆、親友留祝福都要先勾選同意，沒勾選時什麼都不會送出 |

本來就沒問題的：密碼只存 scrypt 加鹽雜湊；懷孕、寶寶、健康紀錄與照片只在手機；錯誤紀錄不含個資；畫面上的 Email／手機會遮蔽；社群功能用的是和帳號無關的匿名代號。

**隱私權政策頁**（我的 → 隱私權政策與使用條款；登入頁、每個勾選框都能直接打開，不會離開正在填的表單）依第 8 條列出：蒐集者、目的、資料類別（逐項寫出存在哪、保存多久）、利用期間／地區／對象／方式、第 3 條的權利與行使方式、不提供的影響；另有敏感資料（第 6 條）、行銷（第 20 條）、安全措施、外洩通知（第 12 條）、使用條款與社群守則、政策更新。內容只寫 App 真的有做的事。

**上線前品牌必須完成**（`mom-app/config.js` 的 `privacy`）：
1. 填 `company`（營運公司全名）、`contact`（個資窗口 Email 或電話）、`region`（會員資料主機所在地區，例如 Vercel／Upstash 的資料中心所在國家）；需要時修改 `processors`。
2. **請律師或法務審閱**政策全文與勾選文字（這裡是依實作內容整理的版本，不等同法律意見）。
3. 建立個資外洩通報流程（第 12 條）與安全維護計畫（第 20-1 條）。
4. 第一次寄行銷訊息時，要在訊息裡提供免費的拒絕方式；只寄給勾選同意的會員（`/me/export` 與資料庫裡的 `marketing.on`）。

### 家族週報（0.7.5）

每週日把這一週整理成一張卡，媽媽一鍵傳到家族 LINE 群組；阿公阿嬤每週都等得到、也最常轉傳，是「每週回來」和「被轉傳」的固定節奏。

**一週怎麼算**
- 一週是週一到週日（手機的當地時間）。週日看「這週」，週一到週六看「剛結束的那週」；剛開始用、上週沒紀錄時改看「這週到今天」。可以往前翻到寶寶出生那週（最多一年）。
- 每天平均只算**有紀錄的整天**：今天還沒過完，不算進平均（除非這週只有今天）；跨夜的睡眠分到兩天；沒結束的睡眠計時最多算 16 小時。
- 瓶餵佔餵奶一半以上就寫「每天喝奶 ml」，以親餵為主就寫「每天餵奶 次」。

**卡片上有什麼**（1080×1920，和其他分享卡同尺寸；下方是邀請 QR）
- 育兒：寶寶名字（可關）、月齡與出生第幾天、每天喝奶／睡眠／尿布、七天長條圖（奶量、餵奶、睡眠、尿布可切換，今天是淡色、還沒到的日子是空格）、這週的大事（出生、滿月、百日、收涎、度晬、生日、新技能、量身高體重與變化、第一次吃的副食品、最長一覺、洗澡、產後坐月子週數、滴雞精時光天數）、媽媽給家人的一句話（選填，40 字）。
- 懷孕（好孕週報）：孕週、寶寶像什麼水果多大、還有幾天見面、數胎動次數、滴雞精時光、整個孕程的進度條、這週的寶寶在做什麼、完成第幾次產檢、待產包進度（30 週起）。
- **不放醫療紀錄**：看診、體溫、用藥、疫苗、產檢檢查項目都不會出現在卡片或文字版。寶寶照片預設不放（要自己勾）。

**怎麼傳**
- 「傳到家族群組」：手機打開分享選單，圖片＋文字一起送（選 LINE → 家族群組）；電腦上下載圖片並打開 LINE 傳文字版。

- 「存圖片」。傳過的週會標「✓ 已傳給家人」，並給好孕點數。

**首頁提醒**：週日（這週）和週一（上週）首頁出現「這週的家族週報做好了」＋兩個關鍵數字；✕ 就這週不再出現；傳過、關掉提醒（週報頁最下面）或這週幾乎沒紀錄（少於 3 天，而且沒有新技能、量身高體重或大日子）時不出現。懷孕時要用 App 3 天以上才提醒。

**入口**：首頁週日提醒、健康 → 家族週報（育兒「紀錄分析」、懷孕「孕期」）、統計與報告、紀錄 → 月曆、孕期週記、邀請好友的分享卡圖庫、搜尋「週報／家人／群組」。

### 雙向邀請禮（0.7.6）

朋友用你的邀請連結（或邀請碼）加入、完成設定並註冊會員時，**兩個人都拿到好孕點數**：朋友拿「見面禮」30 點，邀請的人每一位朋友拿「邀請禮」50 點（`config.js` 的 `inviteGift` 可改）。以前只有邀請的人被計數，被邀請的朋友沒有任何好處，也沒有理由註冊會員。

**朋友這一邊**
- 打開邀請連結：歡迎頁寫「💌 小美邀請你一起使用」和「🎁 註冊會員，你們都有邀請禮」。
- 先試用也行：育兒中是寶寶卡下面的一行「🎁 小美送你的見面禮・註冊領 30 點」，懷孕／備孕是首頁最上面的卡片；點了直接打開「註冊」，邀請碼已經填好，上面寫清楚兩邊各拿到什麼。✕ 可以關掉（14 天後也會自己消失），之後在「我的 → 邀請好友」還是可以領。
- 註冊完（LINE 登入的話是同意隱私權政策之後）、而且 App 設定好了，就自動領取：跳出「🎁 見面禮 +30 好孕點數」，寫邀請的人也收到了邀請禮、解鎖了哪個獎勵，還有「跟小美說聲謝謝」（打開 LINE，只有一句謝謝，不帶連結）。先註冊再設定的人，設定完成那一刻才領。
- 沒用連結加入：註冊後 14 天內，在「邀請好友」展開「有朋友的邀請碼嗎？」輸入朋友的邀請碼（大小寫、空白都可以；搜尋「邀請碼」「見面禮」「好孕點數」也會直接找到這一頁）。打錯、輸入自己的、或連結裡的碼不是會員的，都會清楚說明。

**邀請的人這一邊**
- 「邀請好友」頁最上面就是「🎁 雙向邀請禮」：朋友 +30／你 +50、已有幾位朋友接受邀請、邀請禮共拿到幾點、再邀請幾位就能解鎖下一個獎勵；還沒登入的人會看到「先登入會員再邀請」（沒登入時連結裡的邀請碼伺服器不認得）。
- 朋友加入後，下次打開 App、回到 App、或停在「邀請好友」頁時（每 15 秒看一次）就收到：「🎉 有 1 位朋友接受你的邀請！邀請禮 +50 好孕點數」。**只看得到人數，看不到朋友是誰。**換一支手機登入不會重複發以前的邀請禮（點數本來就記在各自的手機）。
- LINE 邀請的文字多了一句「用我的連結加入、註冊會員，你會拿到 30 點見面禮 🎁」。

**伺服器怎麼判斷**（`mom-api/invite.js`，`POST /invite/claim`）
- 邀請人**不再在註冊時計數**，改成朋友領見面禮時才計入：要同意目前版本的隱私權政策（LINE 新帳號不同意就會被刪掉，以前這種情況也會被算進去）、帳號是 14 天內新建的、每個帳號只能領一次（兩個請求同時送到也只算一次）。
- 計數上限沿用：每個邀請碼每天 30 位、同一個網路每天 3 位；超過時朋友照樣拿見面禮，只是不再計入。
- 自己輸入的邀請碼：不能是自己的、不能是比自己晚註冊的帳號（兩個人互相邀請各拿兩份）、設定後不能更改；每個帳號 10 分鐘最多試 20 次、每個網路最多 30 次。

### 好孕島的限時團購（0.8.6）

**為什麼**：你想要像遊戲畫面左邊那一排活動圖示一樣，有倒數、點了就看到正在開團什麼。本來想放首頁，但首頁每個位置都是常用按鈕，會擋到；你決定只放在好孕島。好孕島本來就是一整張可以拖曳的地圖，最像遊戲盤面。

**好孕島左側的一排小圖**
- 一個小圖代表一件事，排序如下：
  1. 成團了：折扣碼在等她。
  2. 我的團：揪團中，上面寫已經幾人。
  3. 朋友揪的團：從連結來的，寫「等你」。
  4. 還沒參加的團購：寫「限時」和折扣。
- 每個小圖下面都有每秒跳的倒數。三天內顯示「07:40:57」，超過 24 小時就像遊戲寫「53:40:57」；三天以上寫「剩 6 天」。最後一小時倒數變紅。
- 點小圖就打開那個團購（或那一團）。
- 只放得下幾個就顯示幾個，不會蓋到下面的「💜」和小島列。
  - 390×844 的手機放得下 3 個，375×667 放得下 2 個，其餘在「正在開團」看得到。
  - 手機橫放時地圖太矮，就不顯示。
- 按「‹」可以收起來（今天），只留一個「🛒＋數量」的小頁籤，點了直接到團購頁；隔天自動再出現。
- 小圖之間的空隙可以照常拖曳地圖。
- 小圖顏色白天晚上都一樣，字都是白字配深底，對比 5:1 以上。
- 減少動態時小圖不晃動。

**團購頁「正在開團」**
- 每個團購都有：
  - 「距離團購結束」的大倒數（天、時、分、秒）。
  - 省多少錢。
  - 幾人成團、開團後幾小時內湊齊、活動到幾月幾日幾點。
  - 「幾團開過、幾位媽媽參加、幾團已成團」。這是伺服器算的真實總數，不含任何人的資料；參加人數達 3 人才顯示，可在 config.js 的 `groupbuyStatsFrom` 調整。
- 依結束時間排，最快結束的在最上面。
- 從小圖點進來，會捲到那個團購並亮一下框。

**開團畫面**

- API 測試多 3 項：分鐘時間、精確的開始和結束、總數會跟著開團／跟團／退出／成團變動，而且只有數字。

### 即時團購（0.8.7）

**為什麼**：你說「即時團購，繼續幫我操作」。團購要成團，最快的方法是讓正在湊人的團被其他媽媽看到、按一下就能跟。以前只能靠團長把連結傳給朋友。

**正在揪的團**
- 團購頁每個團購下面，列出其他媽媽公開的、還沒滿的團：
  - 團名、幾人了、還差幾人。只差 1 人時標紅色「差 1 人」。
  - 人數進度條、每秒跳的倒數，以及「跟團」按鈕。
- 最接近成團的排最前面；超過 3 團可以「看全部」。
- 按「跟團」直接加入，然後打開那一團。差 1 人的團按下去就成團、拿到折扣碼。
- 自己已經在這個團購的某一團時，就不再顯示「跟團」。
- 這個清單放在「我要開一團」上面：先跟別人的團，或自己開一團。

**即時動態**
- 團購頁最上方一行「● 即時」：誰開了一團、有人跟了某團（幾／幾）、某團成團了 🎉，還有是哪個團購、多久以前。
- 每 4 秒換一則；有新的事時先顯示最新那一則。只顯示最近 24 小時、公開的團。

**自動更新**
- 停在團購頁或好孕島時，每 15 秒更新一次。
- 只換清單和動態那兩塊，頁面不會跳回最上面。

**好孕島**：某個團購有團只差 1 人時，小圖的標籤變成紅色「差1人」（折扣先不放，太擠）。

**公開或不公開（個資）**
- 開一團的視窗多了「公開這一團」，預設勾選，品牌可以用 config.js 的 `groupbuyPublicDefault` 改成預設不勾。
  - 說明文字是：其他媽媽在「正在開團」看得到，可以直接跟團（只顯示團名、人數和剩下的時間；之後也能改）。
- 團長在團的頁面有「公開在『正在開團』」開關，可以隨時打開或關掉。
- 不公開的團永遠不會出現在清單或動態。
- 取消公開或刪除帳號時，團名立刻從清單和動態移除，動態裡改寫「一位媽媽」。刪除帳號後，團長的團照常給其他團員，但改成不公開。
- 隱私權政策的「團購揪團」那一列已加上這段說明；下載我的會員資料也會寫哪一團是公開的。

**伺服器**
- 開團可帶 `public`：沒帶就是不公開，舊版 App 開的團不會突然變公開。
- 新增 `POST /groupbuy/team/:id/public`：只有團長、只有還在湊人的團。
- 新增 `GET /groupbuy/live`：每個團購公開、還沒滿的團（最接近成團的在前），以及最近 24 小時的動態。

### 網頁版一打開就看得到限時團購（0.8.8）

**為什麼**：以前網頁版要先到「我的 → 載入範例資料」才看得到限時團購。你選了「網頁版一打開就看得到」。

**改了什麼**
- `config.js` 新增 `groupbuyPreview: true`。網站沒有會員伺服器時（例如網頁預覽版），一打開就顯示三個標「範例」的限時團購：
  - 好孕島左側的倒數小圖、正在開團、正在揪的團、即時動態。
  - 不用先載入範例資料，用自己的資料也看得到；可以試開團、跟團、模擬朋友跟團到成團。
- 首頁維持原樣：沒有小圖，也沒有範例團購卡片。

**不會讓真的使用者看到範例**
- 只有網站「根本沒有會員伺服器」才算預覽：網址有回應，但回的是 404、403 這類「沒有這個網址」。
- 會員伺服器只是暫時連不上（離線、逾時、太頻繁、伺服器錯誤）時，不會出現範例。
- 正式上線如果沒有接會員伺服器，請把 `groupbuyPreview` 改成 `false`。
- 接上會員伺服器後，只顯示真的團購，這個設定不用改。
- 品牌也可以把 `groupbuyPreview` 改成 `false`，完全關掉。

**測試**
- 好孕島小圖測試 39 → 45 項：
  - 沒載入範例資料也有 3 個小圖，團購頁 3 個都標範例，首頁不變。
  - 關掉預覽就沒有。
  - 會員伺服器暫時連不上（模擬斷線）或回 503 時，不會出現範例；網站回 403 時當作沒有會員伺服器，會顯示範例。

### 擠奶奶量好記（0.8.9）

**為什麼**：你說「再幫我加入可以記錄擠奶奶量」。App 本來就能記擠奶的左右奶量，但不好找也不好用：
- 首頁「擠奶」的 ＋ 只會開始計時，要按「完成」才看得到填奶量的地方。
- 奶量每按一下只加 10 ml，記 120 ml 要按 12 次。
- 首頁看不到今天擠了多少。

**首頁**
- 「擠奶」的 ＋ 改成「＋奶量」，一按就打開記奶量。
- 小圖下面直接寫「今天 250 ml」。
- 計時時 ＋ 一樣是「✓ 完成」；計時改放在記奶量最上面的「⏱ 開始擠奶（計時）」。
- 手機桌面的「擠奶」捷徑還是直接開始計時。

**記奶量**
- 記法：「左右分開」或「只記總量」。切換時會把量帶過去。
- 常用奶量一按就好：每一側 30／50／60／80／100／120；總量 60／90／120／150／180／240。也可以直接打數字。
- 一打開就帶入上次的量，選中的數字會亮起來。
- 下面即時寫「合計 140 ml・上次 110 ml・今天累計 250 ml（2 次）」。補登別天的會寫「這天累計」。
- 時長和「存入母乳庫存」照舊。
- 存檔後的提示寫出奶量，例如「已記錄擠奶・140 ml（左 80／右 60）・已入庫」，可以按「復原」，母乳庫存也會一起復原。

**紀錄**
- 當天摘要下多一行「🥛 擠奶 2 次・250 ml（左 140／右 110）」，按了切到擠奶。
- 篩選多了「擠奶」。選擠奶時上面有「近 7 天擠奶量」長條圖：每天的量、今天亮起來、平均每天幾 ml、每次平均幾 ml。
